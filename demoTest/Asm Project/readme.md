# Asm Project 汇编对照示例说明

## 1. 项目定位

`Asm Project` 是一套用于 C/C++ 源码与汇编代码对照学习的示例集，主要面向逆向工程、汇编语言和编译优化入门。

项目中的程序功能都刻意保持简单，重点不在于业务逻辑，而在于观察以下内容：

- C/C++ 控制流如何转换为条件跳转、循环和跳转表。
- 参数、局部变量、返回值和栈帧如何组织。
- 32 位与 64 位程序在调用约定和寄存器使用上的差异。
- 结构体、指针、数组和虚函数在内存中的表示方式。
- 普通异常、`setjmp/longjmp` 与 C++ 异常处理机制的差异。
- 编译器优化如何删除分支、内联代码和改变程序结构。

每个主题都提供 x86 和 x64 两套 Release 程序，以及对应的 PDB 符号文件和 IDA 数据库，适合直接在反汇编器和调试器中分析。默认情况下，Asm Project 同时提供 `Original` 与 `Reversed` 两份 IDA 数据库，用于对照源码程序和逆向还原结果。

每个架构目录通常包含以下文件：

| 文件 | 说明 |
|---|---|
| `*.exe` | 对应架构的 Release 可执行程序 |
| `*.pdb` | 调试符号，包含函数、变量和源码位置信息 |
| `*Original.exe.i64` | `Original`：由源码程序生成的 EXE 对应的 IDA 分析数据库，作为逆向对照基线 |
| `*Reversed.exe.i64` | `Reversed`：由 cnHHHHHcn 逆向还原或重写后得到的版本对应的 IDA 分析数据库 |

`Original` 表示源程序一侧，`Reversed` 表示 cnHHHHHcn 已经完成逆向分析的版本。两者不是简单的文件副本，而是用于对照“原始实现”和“逆向还原结果”的两套数据库。

如果某些旧目录中暂时只有一个 `*.exe.i64`，该文件可以作为原始版本的基准数据库；新版本目录应优先补齐 `*Original.exe.i64` 和 `*Reversed.exe.i64` 的成对结构。

`Reversed` 数据库中的具体人工分析痕迹、注释统计和已知标注问题见 [Reversed 逆向痕迹说明](./Reversed-traces.md)。

目录中没有 `.sln` 或 `.vcxproj` 工程文件，现有 EXE、PDB 和 IDA 数据库是预先构建好的。需要修改或重新编译时，应为每个源码单独建立 Visual Studio 控制台项目，或使用 MSVC 命令行编译。

## 4. 各示例说明

### 4.1 Branch：分支与编译优化

`Branch` 演示了单分支、双分支、多分支和 `switch`。

源码中的判断数据全部在编译期已知：

- `a = 1`
- `a = 10`、`b = 20`
- `Score = 78`

开启优化后，编译器能够推导出每个条件的唯一结果，并删除不会执行的分支。最终 `main` 基本只保留以下四次输出：

```text
a is not Zero.
a < b
Grade C
Grade C
```

该文件同时保存了优化构建和 `/Od` 构建的 x86/x64 汇编，是观察以下现象的好材料：

- 条件判断被化简为固定输出。
- 不可达分支作为死代码被删除。
- 未优化版本保留显式栈帧、比较和跳转。
- `switch` 可能被编译成跳转表，也可能被编译成比较链。

给出的 x86 `switch` 示例使用跳转表 `jmp ds:jpt_...`，x64 示例使用多个 `cmp/jz`。这说明 `switch` 的实现方式并不固定，取决于目标架构、优化选项、case 数量和值分布。

### 4.2 Loops：循环结构

`Loops` 包含以下几类循环：

- 固定次数 `for` 循环。
- 累加求和。
- 嵌套的九九乘法表。
- 判断素数的循环和提前 `break`。
- 使用 `continue` 跳过不符合条件的迭代。
- `do-while` 与 `switch` 组成的菜单循环。

反汇编时应重点寻找：

- 循环初始化代码。
- 条件比较和退出跳转。
- 循环变量递增位置。
- 跳回循环开头的回边。
- `break`、`continue` 对应的不同跳转目标。

程序运行时会先输出固定内容，然后要求输入一个整数判断是否为素数，最后进入菜单。输入 `0` 可退出菜单。

### 4.3 Pointer：指针、结构体和数组

`Pointer` 实现了一个基于结构体数组的学生成绩管理程序。

```c
struct Student {
    char name[20];
    int  id;
    float score;
};
```

在当前默认布局下，可以重点验证以下偏移：

| 字段 | 偏移 |
|---|---|
| `name` | `0x00` |
| `id` | `0x14` |
| `score` | `0x18` |
| `sizeof(Student)` | 通常为 28 字节 |

源码包含以下指针操作：

- `Student* arr` 指向结构体数组首元素。
- `arr + *count` 计算下一个空位。
- `int* count` 允许函数修改调用者的数量变量。
- `const Student*` 表示只读遍历。
- `p++` 按一个完整结构体的大小移动指针。
- 冒泡排序时使用结构体整体赋值完成交换。

反汇编中可以观察数组下标如何乘以结构体大小，以及 `p->id`、`p->score` 如何转换成固定偏移访问。

程序为交互式菜单，可选择添加学生、显示全部、按姓名查找、按成绩排序和计算平均分。

### 4.4 Call_And_Recursion：调用、栈帧和尾调用

该示例包含：

- 普通阶乘递归。
- 使用累加器的尾递归阶乘。
- 普通递归求和。
- 尾递归求和。
- 直接返回另一个函数结果的尾调用。
- 返回后还要继续计算的非尾调用。

普通递归在调用返回后仍需执行乘法或加法，因此必须保留每一层调用需要的数据。尾递归把中间结果放入累加器，理论上可以直接复用当前栈帧并转换为循环。

分析时应关注：

- 函数序言和函数尾声。
- 参数如何进入被调用函数。
- 返回值使用哪个寄存器。
- 递归时是否不断创建新栈帧。
- 尾调用是否表现为 `jmp`，还是仍使用 `call/ret`。

需要注意，尾调用优化不是 C/C++ 标准强制要求。MSVC 是否将尾递归转换成循环，应结合具体优化选项和实际反汇编判断，不能只根据源码形式推断。

### 4.5 C_try：使用 setjmp/longjmp 模拟异常

`C_try` 使用 `setjmp` 保存当前执行环境，再通过 `longjmp` 跳回保存点，以此模拟 `try/catch`。

程序定义了三个错误码：

- 除零错误。
- 空指针访问。
- 数组越界。

`setjmp` 第一次返回 `0` 时进入正常执行路径；`longjmp` 再次回到保存点时返回传入的错误码，从而进入错误处理路径。

程序实际执行时会先完成 `10 / 2`，随后故意检查一个空指针并触发：

```text
捕获到异常: [2] 空指针访问
```

`longjmp` 只恢复保存的寄存器环境和执行位置，不会执行正常的函数返回流程，也不会自动清理局部对象或资源。因此它适合用来研究底层控制流，不应替代通用错误处理机制。

### 4.6 C++_try：C++ 异常处理

`C++_try` 使用真正的 C++ 异常：

- `DivZeroError` 继承 `std::exception`。
- `NullPtrError` 继承 `std::runtime_error`。
- `safe_div` 在除数为零时抛出异常。
- `check_ptr` 在指针为空时抛出异常。
- `main` 使用多级 `catch` 捕获异常。

程序同样先完成 `10 / 2`，随后触发空指针异常。它的输出与 `C_try` 类似，但底层机制完全不同。

反汇编分析时应关注：

- 异常对象如何构造和传递。
- 异常类型信息如何被使用。
- `try` 范围对应的异常表和处理地址。
- 抛出异常后如何执行栈展开。
- catch 顺序为什么应先捕获派生异常，再捕获基类异常。

在 x64 Windows 程序中，异常处理通常还会涉及 PE 文件的 `.pdata`、`.xdata` 等展开信息。

### 4.7 ClassAndObject_And_STL：对象模型与 STL

该示例包含面向对象和 STL 的核心内容：

- `Animal` 抽象基类。
- 纯虚函数 `speak()`。
- 虚析构函数。
- `Dog`、`Cat`、`Bird` 派生类。
- `vector<unique_ptr<Animal>>` 管理多态对象。
- `typeid` 和 `dynamic_cast` 使用 RTTI。
- `std::sort`、`find_if` 和 `count_if` 使用 lambda。
- 局部对象、拷贝、`std::move` 和析构顺序。

分析虚函数调用时，应重点观察：

1. 对象开头是否存在 vptr。
2. vptr 指向的虚函数表包含哪些函数指针。
3. 通过基类指针调用 `speak()` 时是否产生间接调用。
4. 虚析构函数如何保证派生类析构函数被调用。
5. `typeid` 和 `dynamic_cast` 如何访问 RTTI 信息。

`sizeof(Animal)` 不是固定值，会随 x86/x64、运行库和标准库实现变化。源码注释重点指出 vptr，但对象还包含 `std::string` 和 `int` 等成员，实际大小应以程序输出和调试器观察为准。

`Dog` 声明了自己的析构函数，这通常会抑制编译器生成隐式移动构造函数。因此以下代码很可能仍然调用拷贝构造函数：

```cpp
Dog d3 = std::move(d1);
```

可以在反汇编或调试器中确认实际调用的构造函数，以验证源码语义与编译器生成代码是否一致。

## 5. x86 与 x64 对照

| 项目 | x86 | x64 Windows |
|---|---|---|
| 常用参数传递 | 压入栈 | 前四个整数/指针参数使用 `rcx`、`rdx`、`r8`、`r9` |
| 返回值 | `eax` | `rax` |
| 栈清理 | 通常由调用者清理 | 由调用约定和栈帧共同管理 |
| 常见栈帧 | `ebp` 帧、`[ebp-4]` 局部变量 | `rsp` 相对寻址、固定影子空间 |
| 对齐 | 4 字节栈对齐 | 16 字节栈对齐要求 |
| 典型调用代码 | `push arg`、`call`、`add esp, n` | 设置 `rcx/rdx/r8/r9`、`call` |
| 异常展开信息 | 依赖 x86 异常链 | 常见 `.pdata`、`.xdata` 展开信息 |

x64 程序中经常看到：

```asm
sub rsp, 28h
...
call printf
...
add rsp, 28h
```

其中 `0x28` 通常由 32 字节影子空间和栈对齐组成，不应简单理解成普通的 40 字节局部变量。

```bat

```

## 7. 注释标记约定

`Reversed` 数据库中的注释遵循统一的标记约定，便于在 x86 与 x64 之间对照，也便于保持同一地址上的注释稳定。

### 7.1 基本规则

1. `if` 注释只描述条件跳转，跳转目标必须与反汇编目标一致。
2. `reg:{src}` 中的寄存器名使用目标架构的实际名称，x86 和 x64 不要混用。
3. 栈变量优先写成 `[rsp+偏移+变量名]` 或 `[ebp+变量名]`。
4. 字符串和全局地址使用 `&"字符串"` 或 `ID:{&"字符串"}` 标识。
5. 不能确认的变量名使用地址或 `var_XX`，不要凭空推测类型。
6. 同一地址只保留一条稳定的重复注释，避免重复解释。
7. 分支、函数调用和循环的关键位置优先标记，不必为每条无害指令都添加注释。

### 7.2 标记模式库

| 模式 | 含义 | 示例 |
|---|---|---|
| `if(条件) jmp 地址;` | 条件成立时跳转 | `if(edx == 0) jmp loc_401020;` |
| `jmp 地址;` | 无条件跳转 | `jmp loc_401030;` |
| `reg:{src};` | 寄存器承载的值或地址 | `eax:{[rsp+18h+sum]};` |
| `[addr] = src;` | 把来源写入栈变量、全局变量或内存 | `[ebp+Score(-0x4)] = 78;` |
| `[addr]++;` | 自增 | `[ebp+i(-0x4)]++;` |
| `[addr] += src;` | 累加 | `[ebp+sum(-0x8)] += [ebp+i(-0x4)];` |
| `func(arg:{src}, ...);` | 函数调用及参数来源 | `printf(rcx:{"%d "}, edx:{i});` |
| `&"字符串"` | 字符串地址 | `rcx:{&"请选择："};` |
| `ID:{&"字符串"}` | 带 IDA 名称的字符串地址 | `unk_40314C:{&"是素数"}` |
| `(des:0x地址)` | 跳转目标的绝对地址补充 | `jmp loc_4011AD(des:0x004011F0);` |
| `结束了...` | 函数尾声或主体结束标记 | 位于函数返回前的栈恢复指令旁 |

### 7.3 x86 与 x64 标记差异

同一源码在两种架构下的注释不能机械复制。

| 项目 | x86 标记 | x64 标记 |
|---|---|---|
| 参数 | 主要由 `push` 压栈 | `rcx`、`rdx`、`r8`、`r9` |
| 栈帧 | `[ebp+变量]` | `[rsp+偏移+变量]` |
| 返回 | `eax` | `rax` 或 `eax` |
| 调用前 | 从右向左准备参数 | 写参数寄存器并预留影子空间 |
| 浮点 | 可能使用 x87 栈和 SSE | 常见 `xmm0`、`movsd`、`cvttsd2si` |
| 跳转表 | `jmp ds:jpt_...` | `jmp ds:jpt_...` 或比较链 |

标注时应在同一条注释中保留当前架构实际使用的寄存器和寻址方式，不能把 x64 的 `rcx/rdx/r8/r9` 直接写到 x86 注释中。

## 8. IDA 与 PDB 使用建议

1. 先打开 `*Original.exe.i64`，建立原始程序的函数边界、控制流和关键数据结构基线。
2. 再打开 `*Reversed.exe.i64`，对照原始程序检查逆向还原后的函数布局、调用关系、指令差异和语义变化。
3. 可以直接打开各目录中的 `.i64` 数据库，也可以打开 `.exe`，并让 IDA 自动加载同目录下同名的 `.pdb`。
4. PDB 必须与 EXE 来自同一次构建；版本不匹配时，函数名和源码行号可能无法正确加载。
5. 如果目录被移动，PDB 中的源码路径可能失效，可以在 IDA 的调试器路径设置中补充源码目录。
6. 先定位 `main`，再根据调用关系逐个重命名和分析源码中的函数，效果通常最好。
7. 对比 `Original` 与 `Reversed` 时，优先关注函数边界、导入表、字符串引用、分支结构和关键算法，而不是只比较单个指令是否相同。

## 9. 重新编译

目录中没有工程文件。使用 Visual Studio 时，可以为每个 `.cpp` 新建一个控制台项目，并按需要选择：

- 配置：`Release`
- 平台：`x86` 或 `x64`
- C++ 标准：建议 `C++17`
- 异常处理：`/EHsc`

`ClassAndObject_And_STL` 使用了 `std::make_unique` 等 C++14 及以上特性，建议直接使用 C++17 编译。

在对应的 x86 或 x64 Developer Command Prompt 中，可以使用类似命令：

```bat
cl /nologo /O2 /EHsc /std:c++17 /Zi AsmTest-Branch.cpp /link /DEBUG
```

如果要保留类似 `Branch` 文件中 `/Od` 版本的对照，可再编译一份禁用优化的程序：

```bat
cl /nologo /Od /EHsc /std:c++17 /Zi AsmTest-Branch.cpp /link /DEBUG /OUT:AsmTest-Branch-Od.exe
```

编译器版本、优化选项、运行库和目标架构都会影响最终汇编。分析时应以当前 EXE 的实际反汇编为准。

## 10. 推荐阅读顺序

1. `Branch`：熟悉条件跳转、跳转表和编译优化。
2. `Loops`：熟悉循环条件和循环回边。
3. `Pointer`：熟悉结构体布局、数组寻址和指针算术。
4. `Call_And_Recursion`：熟悉栈帧、参数传递和递归。
5. `C_try` 与 `C++_try`：对比两种异常控制流。
6. `ClassAndObject_And_STL`：分析虚函数、RTTI、智能指针和 STL。

## 11. 注意事项

- `Branch` 中的常量分支在 Release 构建中会被大量优化，若要观察原始判断结构，应查看 `/Od` 版本或把数据改成运行时输入。
- 尾调用优化不是语言标准保证的行为，必须结合反汇编确认。
- `longjmp` 会跳过正常栈展开和资源清理，不等同于 C++ 异常。
- 虚函数、RTTI、STL 和异常处理会产生大量编译器运行库代码，阅读时应先识别源码业务函数，再看运行库辅助函数。
- 优化构建会内联、合并和重排代码，源码行与汇编指令不一定保持一一对应。
- 32 位和 64 位程序的指针大小、结构体布局、寄存器用法和调用约定都可能不同，应分别分析。
